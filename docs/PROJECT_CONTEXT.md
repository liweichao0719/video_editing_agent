# 项目背景与讨论记录

更新日期：2026-07-30

## 1. 项目来源

本目录不是从 GitHub 直接克隆或 fork 的仓库，现有 PoC 代码是在本地讨论和实验过程中创建的。

项目最初受到 [OmniGAIA](https://github.com/RUC-NLPIR/OmniGAIA) 的启发，尤其是其中“主动感知（Active Perception）”和“多模态模型结合外部工具完成任务”的思路。本项目没有直接复制 OmniGAIA 的代码，但如果未来公开，应在 README 和项目介绍中明确致谢其概念启发：

> This project was conceptually inspired by OmniGAIA and its exploration of active omni-modal perception and tool-integrated agents.

当前 Blender 示例视频来自 Wikimedia Commons：[Kitchen blender](https://commons.wikimedia.org/wiki/File:Kitchen_blender.webm)，作者/署名为 Sounds of Changes，采用 CC BY 3.0。公开示例或衍生素材时必须保留相应署名和许可信息。

## 2. 项目演进

最初目标是验证：多模态模型能否同时理解视频画面和声音，并输出结构化事件。

第一次真实实验已经能够输出 JSON 和主要视觉事件，但模型对音频连续状态和时间定位不可靠。因此，仅让模型“描述视频”没有形成真正闭环。

讨论后，将第一阶段定位为“声音触发型视频事件取证 Agent”：

1. 输入视频和目标事件，例如玻璃破碎、敲门或报警。
2. 音频模型提出候选时间段。
3. 多模态模型结合画面进行确认。
4. 调用 FFmpeg 裁剪证据片段并添加说明。
5. 重新检查输出视频是否完整包含目标事件。
6. 输出视频、事件时间和结构化报告。

这一任务本身不复杂，它的价值在于验证通用剪辑 Agent 最核心的闭环：

> 理解素材 → 定位片段 → 执行剪辑 → 检查结果 → 必要时修正

## 3. 长期定位

当前项目不应被写死为“玻璃破碎检测器”。声音事件取证只是通用剪辑 Agent 的第一个垂直任务。

后续计划是在闭环稳定后选择一个具体剪辑领域，例如教学/软件操作视频、访谈播客、游戏高光或产品演示。更换领域时，应尽量只替换领域规则、提示词和评测集，继续复用感知、工具调用、剪辑和结果校验能力。

当前明确不做具身智能或硬件控制，避免引入个人项目无法承担的设备资源。

## 4. 当前资源判断

- 已具备：豆包多模态 API、FFmpeg/ffprobe、基础后端和可视化页面。
- 已验证：模型能够读取测试视频并返回结构化结果。
- 待加入：独立音频事件检测、真实剪辑工具调用、成品复检和量化评测。
- 建议音频模型：YAMNet，用来生成候选时间段，不作为最终裁决者。
- 数据策略：先做约 20 条样本跑通闭环，再扩充到约 45 条正式评测数据。
- 初始事件类别：玻璃破碎、敲门、报警；“机器启动”定义较宽，暂缓加入。
- 生成视频可以用于开发和边界案例，但最终评测必须保留真实视频，避免只在合成分布上有效。

## 5. 公开发布前检查

- 在 README 中致谢 OmniGAIA 的概念启发，并链接其仓库或论文。
- 为每个公开测试素材记录来源、作者和许可证。
- 不提交 .env、API Key、上传视频或其他私人数据。
- 不直接重新发布来源和授权不清晰的 YouTube 数据。
- 明确区分本项目原创代码、第三方依赖、外部模型和测试素材。
- 为实验结果保留模型版本、提示词、输入数据版本和评测指标。

## 6. 下一阶段

第一阶段只实现最小闭环：

> 音频候选定位 → 多模态确认 → FFmpeg 裁剪 → 成品检查 → JSON 报告

完成后用少量正负样本测量误报率、时间定位误差和输出视频完整性，再决定是否扩大数据集或进入具体剪辑领域。

## 7. 决策记录

### 2026-07-30

- 项目长期目标是通用剪辑 Agent，而不是单一声音分类器。
- 第一阶段以“声音事件取证”作为最小可验证任务，因为它范围小，但能覆盖感知、决策、执行和复检闭环。
- 当前任务的价值不在于剪出一个片段，而在于系统能够说明为什么剪这里、检查剪辑结果，并在失败时修正。
- 底层接口和数据结构保持通用，不把玻璃破碎、敲门、报警等类别写死，以便未来切换到教学视频、访谈、游戏高光或产品演示等领域。
- 暂不开展具身智能或硬件控制方向，优先选择个人可获得的软件工具和数据。
- 数据采用混合策略：生成视频用于快速开发和边界测试，真实视频用于最终可信评测。
- 下一步先使用现有 Blender 示例跑通：YAMNet 候选定位 → 豆包音画确认 → FFmpeg 裁剪 → 成品检查 → 页面展示。
- 最小闭环稳定后，再增加敲门、报警、玻璃破碎等正负样本；不在闭环完成前投入大量数据收集。
